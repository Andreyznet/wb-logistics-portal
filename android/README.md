# Маршрут для Android 1.1.0

Android 8.0+ (API 26), рабочие экраны портала https://open-key.ru и нативные уведомления Firebase FCM. Серверный бот работает на VPS независимо от приложения.

## Доставка уведомлений

После входа телефон регистрирует FCM-токен через отдельный защищённый ключ устройства. Заявки направляются автору и подписчикам, события запуска/остановки и подтверждённые ошибки — зарегистрированным сотрудникам. Данные заявки и токен WB не передаются через Firebase: push содержит идентификатор события, детали загружаются с портала с авторизацией. Подтверждения ПК и каждого телефона независимы.

Когда сервер настроен для FCM, постоянный опрос телефоном прекращается. Полученный приоритетный push запускает короткую синхронизацию; служба завершается, если нет неподтверждённых заявок. При заявке служба воспроизводит личный сигнал и вибрацию до ОК, в шторке есть уведомление с данными. Открытое приложение показывает карточку; из фона карточка открывается нажатием уведомления. При пониженном Android приоритете push показывается обычное уведомление для открытия приложения.

До настройки серверных учётных данных действует прежняя резервная связь с длинным запросом ожидания. Ей может требоваться исключение из оптимизации батареи. Статус FCM доступен в профиле → Настройки приложения → Состояние подключения. Отключение фоновых уведомлений не выключает общего бота.

FCM требует Google Play services, сети и разрешения уведомлений. Доставка зависит от сети, Doze и настроек производителя; мгновенная доставка не гарантируется. После принудительной остановки откройте приложение снова. Ключ устройства действует 30 дней; после истечения нужен повторный вход. FCM не обходит запреты Android. Разрешение камеры, контактов или всех файлов не требуется.

## Настройка Firebase на VPS

Проект: `the-route-b9b20`. Android-конфигурация `app/google-services.json` уже подключена. Она не даёт серверу права отправлять сообщения.

1. В Firebase Console открыть проект → шестерёнка → Настройки проекта → Сервисные аккаунты (Service accounts).
2. В разделе Firebase Admin SDK нажать «Создать закрытый ключ» (Generate new private key). Сохранить JSON на своём компьютере и переименовать в `firebase-service-account.json`. Этот файл не отправлять в чат, Git или APK.
3. В настройках проекта → Cloud Messaging проверить, что Firebase Cloud Messaging API (V1) включён. Если выключен, перейти по ссылке управления API и включить Firebase Cloud Messaging API в том же Google Cloud проекте.
4. На VPS создать каталог:

```bash
install -d -m 750 -o root -g logist /etc/logist
```

5. В PowerShell на своём компьютере загрузить ключ (команда предполагает файл в Downloads):

```powershell
scp "$env:USERPROFILE/Downloads/firebase-service-account.json" root@109.248.239.39:/etc/logist/firebase-service-account.json
```

6. На VPS установить права:

```bash
chown root:logist /etc/logist/firebase-service-account.json
chmod 640 /etc/logist/firebase-service-account.json
nano /opt/logist/.env
```

Добавить или заменить две строки в `.env`, сохранив остальные настройки:

```dotenv
FCM_PROJECT_ID=the-route-b9b20
GOOGLE_APPLICATION_CREDENTIALS=/etc/logist/firebase-service-account.json
```

Обновить сервер и перезапустить:

```bash
cd /opt/logist
git pull --ff-only origin fix/archive-demo-login
systemctl restart logist.service
journalctl -u logist.service -n 40 --no-pager
```

В журнале ожидается «FCM: очередь push-доставки запущена». Это подтверждает запуск отправителя, но успешность доставки проверяется на телефоне. Ошибки отправки пишутся без токенов; очередь повторяет запросы с увеличением паузы. При проблемах прав сервисного аккаунта проверить роль Firebase Cloud Messaging API Admin в Google Cloud IAM. Не давать роль Owner ради FCM.

## Установка и проверка

Установить APK 1.1.0 поверх предыдущей версии через кнопку Android на портале. Открыть приложение, разрешить уведомления и войти. В профиле проверить «FCM подключён». Нужен оригинальный ключ подписи — удалять приложение для обновления не требуется.

С ПК отправить безопасное тестовое уведомление своему сотруднику; проверить телефон с включённым экраном, затем со свёрнутым приложением и заблокированным экраном. Проверить звук до ОК, независимое подтверждение на ПК, запуск/остановку бота. Тест уведомления не принимает реальную заявку. Проверить смену аккаунта и отключение уведомлений.

Автоматические тесты проверяют адресную очередь, повторные попытки, отключение устройства, независимость от подтверждения ПК и OAuth HTTP v1. Сборка APK проверяется отдельно. Фактическую доставку через Firebase на физическом телефоне можно проверить только после настройки серверного ключа.

## Сборка

Gradle wrapper 9.6.0, Android Gradle Plugin 9.2.0, Google Services plugin 4.6.0, Firebase BoM 35.2.0. SDK 35, build-tools 36.0.0. Сборка проверена с JBR 25 Android Studio; Gradle 9.6 требует JDK 17+.

```powershell
powershell -ExecutionPolicy Bypass -File android/build-apk.ps1
```

Скрипт использует Gradle и сохраняет результат в `android/app/build/outputs/apk/debug/app-debug.apk`. Первый запуск загружает зависимости. В Android Studio открыть каталог android и указать установленный SDK. Для командной строки можно использовать `android/gradlew.bat -p android :app:assembleDebug`.

Ключ подписи `.local-signing/debug.jks` не хранится в Git. Восстановить исходный ключ из приватной резервной копии; не генерировать новый для обновления установленного приложения. Сборка допускает `-PsigningStore=/absolute/path/to/key.jks`. Пароль и alias текущей тестовой подписи заданы в Gradle; для промышленной публикации требуется отдельная схема хранения секретов подписи.

Лицензии звуков: SOUND-LICENSE.txt и SOUND-SOURCES.md.

Документация: [получение FCM на Android](https://firebase.google.com/docs/cloud-messaging/android/receive-messages), [приоритет сообщений](https://firebase.google.com/docs/cloud-messaging/android-message-priority), [отправка HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api).

## Версия 1.1.1: отзыв доступа и устройства

Обновление сохраняет подпись и устанавливается поверх 1.1.0. Приложение сообщает модель, версию и состояние открытого экрана администратору при входе, смене состояния и не чаще раза в минуту во время работы с экраном. В режиме ожидания FCM отдельного опроса ради присутствия нет.

Администратор может заблокировать логиста или менеджера через «Приложения и доступ». Доступ сервера закрывается сразу. После получения служебного push или HTTP 401 приложение очищает авторизацию, закрывает кабинет и карточки, останавливает фоновую службу и сигнал. Заблокированный сотрудник не сможет войти до разблокировки. Старые версии также теряют доступ к API, но для обработки команды выхода при спящем приложении требуется 1.1.1. При отсутствии сети команда поступит позже. Это выход из учётной записи, а не удалённое завершение процесса Android.

## Версия 1.1.2: повторное окно после ОК

Исправлен порядок подтверждения: нажатие ОК синхронно сохраняет локальное подтверждение и убирает запись из очереди до закрытия карточки. Успешный ответ сервера очищает только очередь отправки, а не признак локального подтверждения. Запоздалый ответ синхронизации не может снова открыть или озвучить подтверждённую запись. Подтверждения передаются перед загрузкой новых уведомлений.

ОК работает и при отключённых фоновых уведомлениях. Для сетевой отправки предусмотрено отдельное задание Android JobScheduler с повтором при восстановлении сети и сохранением задания после перезагрузки; оно не включает отключённые пользователем уведомления. На старте приложение сначала обновляет очередь с сервера и не показывает устаревший локальный список. Из постоянного уведомления удалено действие «Отключить фон»; настройка остаётся в профиле. Диагностика при выключенном фоне явно сообщает, что доставка отключена, даже если FCM зарегистрирован.

Четыре JVM-теста проверяют сохранение подтверждения после ответа сервера/перезапуска, миграцию старой очереди отправки и сохранность других подтверждений. Реальная доставка и поведение конкретного телефона проверяются после установки обновления. Никаких реальных тестовых заявок или звуков во время автоматической проверки не отправляется.
