# Маршрут для Android

Устанавливаемое гибридное приложение для Android 8.0+ (API 26). Все рабочие экраны и роли используют текущий портал `https://open-key.ru`. Системные уведомления, повторяющийся сигнал, подтверждение ОК и фоновая служба реализованы нативно на Java. Веб-интерфейс внутри приложения не запускает второй звуковой сигнал.

## Установка и работа

1. Сначала обновить сервер: `git pull --ff-only origin fix/archive-demo-login`, затем `systemctl restart logist.service`.
2. Передать сотруднику APK и разрешить установку из выбранного источника. Войти с обычным логином и паролем портала.
3. Разрешить уведомления Android. После входа телефон регистрируется отдельным защищённым ключом устройства на 30 дней, затем включается фоновая связь, если пользователь не отключил её в меню. Ключ хранится зашифрованным с использованием Android Keystore; сервер хранит только хеш. В шторке появится постоянное уведомление «Маршрут · фоновая связь».
4. Подтвердить системный запрос исключения из оптимизации батареи; через профиле → «Настройки приложения» → «Работа без ограничений батареи» проверить разрешение; на устройствах некоторых производителей разрешить автозапуск. Убедиться, что системная громкость будильника не равна нулю.
5. В профиле портала выбрать личный сигнал и громкость. Эти же настройки использует нативный проигрыватель. Каналы событий и заявок настраиваются в системных настройках уведомлений.
6. Для безопасной проверки менеджер может использовать «Проверить уведомление» в настройках бота — запрос принятия WB при этом не отправляется.

При принятии или обнаружении заявки сотрудника (либо заявки, на которую он подписан) приходит приоритетное системное уведомление, играет личный сигнал и вибрация до ОК. Если приложение открыто, показывается окно с подробностями. В фоне нажать на уведомление для просмотра данных или на ОК прямо в шторке. Нажатие ОК сохраняется локально и отправляется серверу; при отсутствии сети подтверждение повторяется после восстановления связи. Подтверждения на ПК и на каждом телефоне независимы. ОК в браузере не убирает уведомление из очереди телефона. Срок ключа устройства — 30 дней; пароль и токен WB телефону не передаются.

Запуск, остановка, ошибки бота/API и восстановление связи приходят отдельными уведомлениями без бесконечной сирены. Повторяющиеся одинаковые ошибки ограничены одним уведомлением за пять минут. На экране постоянно видны состояние бота и актуальность связи.

## Ограничения Android

- Свернуть приложение или убрать его из списка последних — серверный бот продолжает работу, служба при включённом фоне остаётся активной. Бот исполняется на VPS, не на телефоне.
- Это корпоративная APK-сборка с пользовательской непрерывной фоновой службой `specialUse`, не Firebase/FCM. Телефон удерживает запрос ожидания; сервер проверяет изменения каждые 200 мс и отвечает при появлении события. Между соединениями пауза около секунды. Это убирает 15-секундный интервал; задержки мобильной сети возможны. Для публикации в Google Play потребуется рассмотрение назначения этой службы. Для массовой публикации разумно отдельно подключить FCM и серверную доставку.
- Во время фоновой смены используется ограниченная по времени и регулярно возобновляемая CPU-блокировка, поэтому батарея расходуется сильнее. Полностью выключить фон можно в меню приложения или в постоянном уведомлении. Это не выключает общего бота на сервере.
- При выключенном интернете, ограничениях батареи, блокировке уведомлений системой или принудительной остановке доставка может задерживаться. После перезагрузки телефона или принудительной остановки нужно открыть приложение. Приложение не обходит системный запрет фоновых запусков и не открывает окна поверх других приложений без действия пользователя.
- Истечение сессии портала останавливает фоновую связь и выдаёт уведомление о необходимости входа. Не хранится пароль или токен WB: для фона используется отдельный ограниченный ключ устройства, для экранов портала — cookie WebView. Резервное копирование данных приложения отключено.
- Все внешние ссылки открываются браузером. Ошибки HTTPS не игнорируются. JSON-выгрузки сохраняются через системный диалог; выбор файлов аватара/импорта — через системный проводник.

## Сборка

В Android Studio открыть каталог `android`. Проект использует Android Gradle Plugin 8.7.3, Gradle 8.9, JDK 17, SDK 35. Внешних Java-библиотек нет. Для Gradle: `gradle :app:assembleDebug` при установленном совместимом Gradle; wrapper в репозитории не требуется для ручного способа ниже.

На Windows доступна автономная сборка средствами установленного Android SDK:

```powershell
powershell -ExecutionPolicy Bypass -File android/build-apk.ps1 -SdkRoot "$env:LOCALAPPDATA/Android/Sdk"
```

Нужны `build-tools/36.0.0`, `platforms/android-35`, JDK 17+ (по умолчанию JBR Android Studio). Результат: `android/app/build/manual/marshrut-1.0.2.apk`. Скрипт выполняет aapt2 → javac → D8 → zipalign → apksigner и проверяет подпись.

Текущая APK подписывается локальным ключом разработки `.local-signing/debug.jks`; он не коммитится. Сохранить этот ключ для совместимых обновлений тестовой установки. Для промышленного распространения выпускать релиз с постоянным ключом организации, который хранится отдельно от Git. При смене ключа Android потребует удалить старую установку.

Лицензии звуков находятся в `SOUND-LICENSE.txt` и `SOUND-SOURCES.md`.

## Проверка на телефоне перед эксплуатацией

- Войти логистом; проверить заявки, поиск справочников, создание и паузу плана, подписку, профиль, базу знаний и выгрузки по своей роли.
- Выдать разрешение уведомлений, свернуть приложение, заблокировать экран. Менеджером отправить безопасное тестовое уведомление. Проверить доставку, звук, открытие данных и ОК.
- Проверить включение/остановку бота и ошибки API на тестовом сервере, не создавая реальные принятия WB.
- Выключить сеть, нажать ОК в уведомлении, восстановить сеть: событие должно подтвердиться без повторной сирены.
- Выйти и войти другим сотрудником: события предыдущего аккаунта не должны появляться.
- Отключить фон: постоянное уведомление и сирена должны исчезнуть. Повторно включить из меню приложения.

Ограничения платформы: [разрешение уведомлений](https://developer.android.com/develop/ui/views/notifications/notification-permission), [типы foreground-служб](https://developer.android.com/develop/background-work/services/fgs/service-types).

## Исправления 1.0.1

Добавлен прямой запрос исключения из Android Doze, проверка разрешения в строке подключения и переподключение по восстановлению сети. CPU-блокировка обновляется при каждой проверке без 10-минутных разрывов. Обычные включения/остановки бота не подавляются ограничителем повторяющихся ошибок. Исправлены общая очередь ПК/телефона и зависимость фоновой авторизации от WebView. Обновление устанавливать поверх 1.0.0 после обновления сервера; ключ подписи тот же.

## Версия 1.0.2

Дополнительная нативная шапка удалена; диагностика и настройки приложения доступны из профиля портала. Окно заявки оформлено округлой карточкой с оранжевой кнопкой Ок, цветами светлой/тёмной темы портала и прокруткой только списка данных при нехватке места. При первом запуске (и после этого обновления) открывается пошаговая настройка уведомлений и исключения из оптимизации батареи; пользователь может отказать. Камера, контакты и доступ ко всем файлам не требуются.

Фиксированный 15-секундный опрос заменён длинным запросом ожидания событий (до 25 секунд). Сервер отвечает сразу после появления уведомления/изменения состояния; клиент открывает следующее ожидание примерно через секунду. Нажатие ОК прерывает текущее ожидание и обрабатывается сразу. Разрывы сети повторяются с увеличением паузы. Тест сервера подтверждает доставку события без ожидания прежнего интервала; реальная задержка на телефоне зависит от сети и ограничений ОС.
